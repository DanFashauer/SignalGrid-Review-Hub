# Demo Script for Partners

This script references only current validated Review Hub assets. It is designed for public-safe walkthroughs and should not be presented as a production system, compliance artifact, live integration, current partnership, or acquisition offer.

## Demo assets to reference

- Review Hub.
- Connector Emulator Dashboard.
- Credential Reader / Smart Locker Dashboard.
- Connector Emulator Smoke evidence.
- Autopilot Control Plane.
- Strategic Buyer / Partner Pitch Pack.

## Script

### 1. Set the boundary

"This is the SignalGrid Review Hub, the public pre-production review and validation surface. Everything shown here is synthetic and fixture-backed. There are no credentials, tenant IDs, customer data, PHI, PII, real vendor API calls, real Microsoft Graph calls, or production integrations in this demo."

### 2. Explain the orchestration problem

"In shared, mobile, and frontline environments, the decision is rarely contained in one system. Identity, device posture, credential-reader events, custody, network context, workflow ownership, and audit evidence all matter. SignalGrid is exploring the orchestration layer that normalizes those signals and routes approval-gated outcomes while source systems remain the systems of record."

### 3. Show the Review Hub

Open the Review Hub documentation map and orient the viewer to the validated public materials, emphasizing that the repository is a review and validation surface rather than a production deployment package.

### 4. Show the Connector Emulator Dashboard

Walk through synthetic connector scenarios that demonstrate signal normalization, decision flow, route owner, approval gate, guardrail, and evidence review. Emphasize that the dashboard proves the review model, not live connector support.

### 5. Show the Credential Reader / Smart Locker Dashboard

Use the credential-reader and smart-locker narrative to explain badge events, custody transitions, dock/locker context, shared-device workflows, and approval gates. State that this is vendor-neutral and fixture-backed.

### 6. Show Connector Emulator Smoke evidence

Reference the Connector Emulator Smoke evidence as the deterministic proof artifact for current connector-emulator scenarios. Explain that proof artifacts support review discipline and do not indicate live vendor operation.

### 7. Show the Autopilot Control Plane

Explain that Autopilot defines scoped execution, risk lanes, backlog curation, validation evidence, and owner-controlled merge flow. It is a governance model for Review Hub work, not autonomous production remediation.

### 8. Reference the Strategic Buyer / Partner Pitch Pack

Use the pitch pack to summarize the strategic category, target partner types, founder-control preference, staged readiness path, and guardrails.

### 9. Close with the next validation question

Ask which signal, workflow, or integration boundary the partner would want to validate first in a private sandbox review. Confirm that any live integration would require separate owner approval, safe test boundaries, and private validation.
