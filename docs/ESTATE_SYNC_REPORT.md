# Estate sync report — every repository, every branch

> **The standing complaint this exists to answer:** work lands in one repository
> and the rest of the estate silently drifts, so the product never feels
> full-circle. This is the first pass that enumerated the whole estate rather
> than the one repository a session happened to be sitting in.

Generated by inspecting the live GitHub estate and cloning what is reachable.
Every claim below states how it was checked. Where a repository could not be
reached, that is recorded as **BLOCKED** rather than assumed clean — an
unexamined repository is not a synchronised one.

**Method.** `list_repos` for the inventory · `git ls-remote --heads` for branch
counts · shallow clone + source inspection for cross-repo claims · live HTTP for
published surfaces.

## 2. Cross-repo claim verification

### 2.1 `signalgrid-mcp` tool surface — ✅ VERIFIED, NO DRIFT

`docs/API_ACCESS_AND_CONNECTORS.md` claims signalgrid-mcp ships **22 tools at
v1.0.2**. That figure is designed to be derived from a checkout by `verify:all`
and printed **UNVERIFIED** when no checkout is present — and in practice no
session had ever had the checkout, so the number had never actually been read.

It has now been read. Cloned at `369e08e` (`main`):

- **22 tool registrations**, counted across the 16 modules in
  `src/signalgrid_mcp/tools/` (users, report, removable_media, sysext, backup,
  mdm, verdict, processes, apps, screen_lock, codesign ×1; identity, security,
  launchd, network ×2; software ×3).
- `pyproject.toml` → `version = "1.0.2"`.

**Both halves of the claim hold exactly.** The head also matches
`BUILD_BACKLOG.md`'s record of PR #12 landing `369e08e` on 2026-08-06 — so the
backlog entry is accurate too. This is the good case, and worth stating plainly:
the mechanism designed to prevent drift did prevent it.

### 2.2 Published web surface — ❌ DRIFT FOUND (fixed in code, owner action pending)

`https://danfashauer.github.io/SignalGrid-Review-Hub/` returns **200**, but serves
the **default Jekyll render of README.md**, not the marketing site. The real site
had never been deployed: `pages.yml` is `workflow_dispatch`-only and had never
been run. Three defects were fixed in this pass (CNAME made opt-in, base path
derived rather than hardcoded, social-preview URLs made absolute — see the commit
for detail). The build job now succeeds; the **deploy job is rejected by the
`github-pages` environment**, which accepts deployments only from the default
branch. Owner action required.

`signalgrid.app` resolves to `192.64.119.253` — a registrar park page, not GitHub
Pages. The domain is registered but not pointed.

**Addendum, 2026-08-12 — the site is live, and the merge surfaced a second
builder nobody had accounted for.** PR #152 merged, which satisfied the
`github-pages` environment's default-branch rule without any settings change,
and the dispatched `pages.yml` run deployed the real site (HTTP 200, marketing
site rather than the Jekyll README render). But the same push also woke
GitHub's **legacy Jekyll builder**, which follows symlinks and died on a
scanner test fixture — a deliberately circular directory symlink proving the
scanner never traverses one. Two builders, one repository, and only one of them
was in anybody's model. Fixed in #202 by pointing the fixture's symlink outside
the scan root without making it a cycle; the fixture still proves what it
proved. **The durable fix is still an owner click: Settings → Pages →
Source = "GitHub Actions"**, which retires the legacy builder entirely so it
cannot trip over a future fixture.

## 3. Branch sprawl — the estate's biggest hygiene problem

**124 branches across four repositories** at audit time, the overwhelming
majority stale. **Review-Hub is now at 11** (2026-08-12): four merges — #152,
#202, #203, #204 — auto-deleted their branches, and the count below is the
audit-time figure kept for comparison rather than a current reading. DEV's 99
are untouched and remain the estate's loudest artifact.

Original audit-time counts:

- **DEV — 99 branches.** Roughly 70 `codex/*`, several `chatgpt/*`, a dozen
  `feat*`/`fix/*`, two Dependabot. This is a public repository whose description
  is the single word "Home". Anyone browsing the account sees it.
- **signalgrid-mcp — 13.** 12 merged-or-abandoned `claude/*` and `fix/*` topic
  branches plus `main`.
- **SignalGrid-Review-Hub — 10.** 7 Dependabot, 1 probe, the launch branch, the
  default branch.
- **VaultLens — 2.** One stale `codex/*` plus `main`.

**Not actioned here, by policy.** Branch deletion is destructive and requires
owner approval; this report identifies and recommends, it does not delete. The
recommendation is to prune every branch already merged into its default branch,
starting with DEV, and to decide whether DEV should remain public at all — it is
the loudest and least representative artifact in a portfolio otherwise built
around provable rigour.
