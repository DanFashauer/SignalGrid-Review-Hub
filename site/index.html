Context-aware trust & orchestration

Trust decided in the moment a workflow fires.

SignalGrid is a runtime decision layer for shared, mobile, and frontline devices. It fuses identity, device posture, workflow risk, and real-world context into a single allow / step-up / restrict / deny decision — then orchestrates the next action, with a human kept in the loop for anything sensitive.

It's a full platform, not a web page — delivered as hosted SaaS or self-hosted / on-prem, with native mobile and desktop apps, an admin console, an API + connector ecosystem, and an optional docking-station hardware layer. The demo below is just the fastest way to watch the engine decide.

The idea

One equation, decided at the edge of every workflow.

Most access is decided once, at login. But a shared tablet on a ward, a frontline scanner, or a kiosk changes hands, moves rooms, and runs high-stakes workflows all shift long. SignalGrid re-decides trust per workflow, in context.

Deterministic core

Explainable, not a black box

Every decision carries the evidence and reason codes that produced it. The core is deterministic — same inputs, same decision, every time — so it can be audited and replayed.

Human-centered

Removes friction, keeps judgment

SignalGrid removes repetitive friction while preserving explicit controls, auditability, and human judgment. Sensitive steps are never silently automated — they're held for a person to confirm.

Public-safe by design

Fixture-first

The whole platform runs on synthetic fixtures by default. No secrets, no PHI/PII, no live vendor calls — live integrations stay gated behind explicit configuration.

The decision

Four outcomes, plus a human-confirmed assist.

Not a binary gate. SignalGrid grades the moment and routes it to the proportionate response.

Allow low friction

Identity, device, and context all clear for this workflow — proceed, and orchestrate the supporting actions automatically.

Step-up re-verify

Confidence is close but not enough — challenge for a passkey / badge tap, then continue once satisfied.

Restrict reduced scope

Let the safe part of the workflow proceed while holding back the risky capability.

Deny fail-closed

A hard signal (custody lost, tamper, disabled account) blocks the action — with the reason on record.

Assist human confirms

The safety rail: even on an allow, a sensitive downstream step (unlock a controlled cabinet, activate a clinical display) is never actuated automatically — it's surfaced for a clinician to confirm. SignalGrid plans; a person decides the sensitive move.

How it works · Trusted Room Entry

A nurse walks up to a room. Here's the moment.

The flagship scenario — one of eight in the live demo — shows the full pipeline: signals in, decision out, orchestration planned, sensitive steps held.

  1. Signals arrive.

    Identity (badge-bound, enabled), device posture (managed, compliant, encrypted, baseline aligned), custody & dock state, and workflow risk tier for what's about to happen.

  2. The core evaluates.

    Twelve signal categories become weighted evidence → a single decision with reason codes. Deterministic and explainable.

  3. Orchestration is planned.

    The decision becomes a plan of downstream actions — session start, environment, alert routing — each tagged auto, assist, step-up, or blocked.

  4. Sensitive steps wait for a human.

    Opening a controlled-medication cabinet or activating a patient display is held with a Confirm button. The clinician stays in control; the audit trail captures it.

Hardware layer · optional

⎓
SmartDock docking station

A smart-charging dock that also holds custody — device seating, tamper-evidence, charge & thermal health — streamed as normalized signals. It charges and connects to the network; the decision still happens in SignalGrid.

▦
Badge / RFID reader case

Binds the physical badge to the device at the point of custody, so "who is holding this right now" becomes a real, live signal — not an assumption.

◉
Custody, dock & tamper signals

The physical world becomes decision input: docked or in-hand, badge bound or withdrawn, seated or tampered — high fidelity, real time.

The hardware layer is an optional, pre-production design concept — SignalGrid runs fully on software-only signals (MDM/UEM posture, identity, baseline) today. Hardware adds the physical signals only a device at the point of custody can produce.

Integration paths

API
/v1 REST API

The deterministic decision core over HTTP, described by an OpenAPI 3.1 contract. Tenant derived from the token.

⇄
Webhooks

React to decisions instead of polling — HMAC-signed delivery with retries and a deliveries log.

MCP
Model Context Protocol

An MCP server exposes SignalGrid as tools, so an AI assistant or agent can query the grid directly.

▷
Postman collection

Every endpoint, ready to import and click — kept in lockstep with the spec by CI.

⊕
Connectors

Adapters that normalize a vendor's data into signals — ITSM, UEM, NAC, SIEM, EDR — fixture-safe by default.

◎
Signal Radar

Watches incoming signals, classifies each as evaluated / candidate / novel, and raises a first-seen alert on anything new.
