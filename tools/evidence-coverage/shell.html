Evidence coverage — what can your systems actually tell us?

The decision engine reads a fixed set of evidence axes. Tick the source planes your deployment really has, and this reports which of them you can answer, which are dark, and — the row that matters — which are dark and ungraded, where the engine returns a grant and nobody sees a finding. This report is fail-closed by construction: an undeclared plane can never make an axis answerable, so every number gets worse as the estate gets thinner. The engine is the opposite on the ungraded axes, and that is exactly what the silent-hole count measures.

Which of these do you have?

Why this and not a replay of your history. A backtest of your existing exports would leave every dark axis absent for every row by construction, and the engine — deliberately quiet on those axes so a pending integration cannot block a fleet — would emit clean grants at scale. Those grants would have come from absence of data, on the one product whose claim is that it refuses to convert silence into a pass. This says the same thing without the lie.

Nothing here reads customer data or calls a connector; the page holds no network code at all. The silent hole markers come from a flag on the axis table that is verified against the shipped rule set offline by proof:evidence-coverage, which runs the real engine over each axis's ignorance member — this page does not evaluate policy.
